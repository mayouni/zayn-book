## 1. What the chapter does

It takes the AI agent as the one who uses an interface, not the one who writes it, and shows that a declaration an AI agent
operates is judged by the same rules as one a person operates. It runs the same declaration on a screen and on the machine
medium and gets the same refusal; it runs what an AI agent needs from an interface it operates (the state declared, a way back,
a named authority behind each act) on the machine medium; and it shows the refusal an AI agent can read, the machine form of the
report. It then shows what the medium changes: which verbs are carried and which statuses are rendered, read from the data
(`media.json`, `signal.json`), and what stays a person's judgment. Chapters 1, 12, 13 and 17 already put a plate on the machine
medium or on `PROPOSAL_COMMITS`: this chapter cites them and repeats none of their plates.

## 4. The principle

The record returns to one sentence, in two files:

> "What a screen reader can operate, an agent can operate and a non-visual medium can render; legibility is one law with three
> beneficiaries." (`constitution/rules.json:2574`, Rule 104's why; the same words in the machine medium's note,
> `conformance/media.json:109`)

and the site states the consequence for this chapter: "An interface for an agent is an interface: the agent is the user at the
other end" (`site/beyond.html:114`).

Proposed bold sentence, in the book's words: **A declaration that an AI agent operates is judged by the same rules as one a
person operates; the medium it names changes only what can be carried and what can be shown.**

Alternative, closer to the user: **When an AI agent is the user, its interface owes it what the law asks of any interface: the
state declared, a way back, and a name behind every act.** (The preamble's carve-out, section 12 finding 4, bounds this one: use
it only with that sentence beside it.)
